# Configuration reference

These settings are read from the environment when [Config](../../src/config.ts) is imported. Set them **before starting Node**. Setting an environment variable after importing the engine does not recompute Config. Browser builds use the platform defaults rather than a Node process environment.

For example, to use a 64 KiB operator memory budget for one experiment:

PowerShell:

```powershell
$env:QE_MEMORY_LIMIT_BYTES = '65536'
npm run book:query
Remove-Item Env:QE_MEMORY_LIMIT_BYTES
```

Unix shell:

```bash
QE_MEMORY_LIMIT_BYTES=65536 npm run book:query
```

The small query may not spill. [Chapter 39](../04-execution/39-memory-and-spilling.md) describes a workload that does. The budget is an operator accounting input, not a strict limit on the Node process's resident memory.

## Reading defaults

The table reproduces default expressions from the source. `1 << 28` means 268,435,456 bytes (256 MiB); `DEFAULT_CHUNK_SIZE` is 2,048. `memoryLimitBytes` and `defaultRowWidthBytes` refer to their resolved settings. For `QE_PARALLEL_WORKERS`, a nonpositive value selects the engine's automatic CPU-based count.

Boolean parsing is defined in [platform.ts](../../src/runtime/platform.ts); use `0` or `1` when setting flags. A setting's presence does not prove an active code path uses it. For example, [chapter 45](../06-scale/45-morsel-driven-parallelism.md) distinguishes `QE_MORSEL_SIZE` from `QE_AGG_MORSEL_ROWS`. `DEFAULT_CHUNK_SIZE` itself has no environment variable.
